## 1. Root Cause: `GlobalsKept` Quantifies Over `String` Through Non-Injective `ofString`

Every contract in `m00` is a `WorldKeeps WorldOK ... gw ...` contract (`campaign/specs-proposed/GuestInv.lean:8941–8979`)
with `"heap_ptr" ∈ gw`:

- `wk_account_deployable`: `gw = ["heap_ptr", "scratch_ptr"]`
- `wk_add_balance_change`: `gw = ["heap_ptr"]`
- `wk_add_code_change`: `gw = ["heap_ptr"]`
- `wk_add_nonce_change`: `gw = ["heap_ptr"]`
- `wk_add_storage_write`: `gw = ["heap_ptr"]`
- `wk_alloc`: `gw = ["heap_ptr"]`

In frozen revision 9 (`GuestInv.lean:6813–6814, 6834–6847`), `WorldStep` requires `GlobalsKept gw s post`, defined as:

```lean
def GlobalsKept (gw : List String) {F : Type} (s post : PanSemStateFiniteExact 64 F) : Prop :=
  ∀ name, name ∉ gw → s.globals.lookup (ofString name) = post.globals.lookup (ofString name)
```

However, `s.globals` is keyed by `MlString`, and `Flapjack.Basis.Pure.MlString.ofString : String → MlString`
truncates each Unicode scalar value modulo 256 (`Char` → 8-bit byte). Therefore `ofString` is not injective on `String`:
for `name = "Ũeap_ptr"` (`'Ũ' = U+0168`, `0x168 % 256 = 0x68 = 'h'`),

```lean
ofString "Ũeap_ptr" = ofString "heap_ptr"
"Ũeap_ptr" ∉ ["heap_ptr", "scratch_ptr"]
```

(Checked in `Common.lean`: `ofString_heap_ptr_alias`.)

Consequently, on **any** `WorldOK` entry state `s` from which the function resumes (`some (.returned v)`)
and strictly advances `heap_ptr` (`p ≠ q`), instantiating `GlobalsKept gw s post` at `name = "Ũeap_ptr"`
forces `some (.val (.word p)) = some (.val (.word q))`, a contradiction (`Common.lean`: `refute_worldKeeps_of_heap_change`).

All 6 functions in `m00` allocate on the bump heap (`alloc`) on valid `WorldOK` inputs and return normally.

## 3. Recommended Spec Fix (for Next Spec Revision)

Quantify over `MlS` (`MlString`) keys in `GlobalsKept` (and in `HtabExit`, `UnionExit`, `HtabNewExit`,
`NodeFnExit`, `MptObjStep`, `EvmStep` where the same `ofString name` global-frame idiom appears):

```lean
def GlobalsKept (gw : List String) {F : Type} (s post : PanSemStateFiniteExact 64 F) : Prop :=
  ∀ k : MlS, k ∉ gw.map ofString → s.globals.lookup k = post.globals.lookup k
```

No other defect was found in the 6 `m00` contracts:
- `alloc` checks `cMax - p < n` and `cMax < q` (`q = (p + n + 7) & -8`) and traps on overflow, preserving `ArenaReady`, `WorldTypedWith` (`S' = S`, `Nd' = Nd`), `OwnedGrows`, `FrameOutside` (memory unchanged), and `RetAvoids [(p, (n + 7) / 8 * 8)]` since `worldOwned s S Nd` lies inside `[sourceBase, p) ∪ [scratch_ptr, scratchEnd)`.
- `account_deployable` writes only fresh heap (`acct_empty` → `alloc(56)`), `ts+8`, `ts+40`, and `scratch` (inside `ws_account_has_storage`), all within `WorldOK` + `["heap_ptr", "scratch_ptr"]`.
- `add_balance_change`, `add_code_change`, `add_nonce_change`, and `add_storage_write` mutate only `bal_accounts`, `bAdRec + 0` (`bal.stor`), the owned BAL list headers/arrays in `balObjects`, and fresh heap (`alloc`), preserving `WorldTypedWith` (`S' ⊇ S`) and `RecordsKept` for `ws`, `bs`, `ts`, `bo`.

# Counterexamples for False Contracts in Micro-Shard `m04` (`wave8-spec-frozen-r9`, `8a79d9f28`)

Two of the six contracts assigned to `campaign/contracts/micro/m04` are **FALSE** on the real guest code (`Guest/SoftwareAst.lean`) because their precondition is `WorldOK` alone, with **no structural or non-overflow guard** on the caller-supplied pointer parameter (`logs` in `wk_encode_receipt`, `tx` in `wk_encode_transaction`). Both functions size their `alloc` buffer using unchecked 64-bit modular arithmetic over fields loaded from that unguarded pointer, allowing the `alloc` size to wrap modulo $2^{64}$ to a tiny allocation near `heapLimit = 0xb0000000` while the subsequent encoding `memcpy` writes past `0xb0000000` into allocated scratch (`[scratch_ptr, scratchEnd)`), corrupting world-owned objects (`ws`) and returning normally (`some (.returned …)`).

## 1. `wk_encode_receipt` is FALSE (`campaign/specs-proposed/GuestInv.lean:9091`, AST line 32051)

### Frozen Statement (`GuestInv.lean:9091–9095`)
```lean

    WorldKeeps WorldOK (fun _ => [])
    ["heap_ptr"]
    [("ws", [0, 8, 16, 24, 32]), ("bs", [0, 8, 16, 24, 32, 40, 48, 56, 64, 72]),
     ("ts", [0, 8, 16, 24, 32, 40, 48, 56, 64]), ("bo", [0, 8, 16, 24, 32, 40, 48, 56, 64, 72, 80])]
    NoExtra (ofString "encode_receipt")
```

### Root Cause in Real Guest Code
1. `encode_receipt(tx_type, succeeded, cumulative_gas, logs)` (`Guest/SoftwareAst.lean:32051`) calls `bound := logs_encoded_bound(logs)` (`AST:31985`) and allocates `buf := alloc(bound + 400)`.
2. For each `i <s n` (`n = memW(logs + 8)`, `p = memW(logs + 0)`), `logs_encoded_bound` loads `log = memW(p + 8*i)` and updates `total` modulo $2^{64}$:
   $$\text{total} \leftarrow (\text{total} + 64 + \text{memW}(\text{log} + 16) \cdot 33 + \text{memW}(\text{log} + 32)) \bmod 2^{64}.$$
3. Both `logs_bloom` (`AST:31957`) and `encode_logs` (`AST:32025`) iterate over topics with a **signed** loop test `Cmp.less j nt` (`nt = memW(log + 16)`). When `nt ≥ 2^63` (signed negative), the inner topic loops in `logs_bloom` and `encode_logs` execute **0 iterations** (writing 0 topic bytes), whereas `logs_encoded_bound` still adds `nt * 33 (mod 2^64)` (and $\gcd(33, 2^{64}) = 1$).
4. Note: even with `nt = 0`, two logs (`n = 2`) with `dlen_0 = 2000` and `dlen_1` chosen or `nt` chosen wrap `bound` before `alloc`; with `nt ≥ 2^63` a **single** log (`n = 1`) suffices and `encode_receipt` completes and returns normally!

# Counterexamples for False Contracts in Micro-Shard `m05` (`wave8-spec-frozen-r9`, `8a79d9f28`)

Five of the six contracts assigned to `campaign/contracts/micro/m05` (`wk_header_init`, `wk_fork_init`, `wk_header_hash`, `wk_get_account`, `wk_get_code`) are **FALSE** on the real guest code (`Guest/SoftwareAst.lean`) against the frozen rev9 specification (`campaign/specs-proposed/GuestInv.lean:9121–9155`). Only `wk_extract_deposit_data` is true (proved in `campaign/contracts/m05/wk_extract_deposit_data.lean`).

The five false contracts fall into two root causes:

1. **Unguarded zero-length `journal` entry in `fixedObjects` + non-zero-exempt `Disj`** (`wk_header_init`, `wk_fork_init`, `wk_get_account`, `wk_get_code`):

/-- **Obstruction Theorem 3 (Post-call receipt-log bound gap)**:

/--Strengthened transaction guard `TxReadyStrong`:
1. `TxReady s` (`WorldOK`, `bo ≠ 0`, `bo+24 ≠ 0`, `bo+32 ≠ 0`, `index < bo+80`),

def TxAccessListOK {F : Type} (s : PanSemStateFiniteExact 64 F) (S Nd : List Nat) : Prop :=
  let tx := locN s "tx"
  let nal := memW s (tx + 216)
  let recs := memW s (tx + 208)
  tx % 8 = 0 ∧ Inside (tx, 384) sourceBase (globN s "heap_ptr") ∧
  (∀ o ∈ worldOwned s S Nd, Disj (tx, 384) o) ∧
  (memW s tx ≠ 0 →
    nal < 2 ^ 32 ∧
    (0 < nal → recs % 8 = 0 ∧ Inside (recs, 24 * nal) sourceBase (globN s "heap_ptr") ∧
      ∀ o ∈ worldOwned s S Nd, Disj (recs, 24 * nal) o) ∧
    ((List.range nal).map (fun i => memW s (recs + 24 * i + 16))).sum < 2 ^ 32)
