# R11 ownership repair

Base: `664524baaf0aff6938ff399c2017a85b8ccc0c59` (`wave8/spec-r10`).

`MarksOK` now requires every surviving ancestor's message record to be on the
heap or above the child's scratch release mark. The depth-zero message is
allocated on the heap. `child_message` allocates a scratch message before any
later grandchild takes its scratch mark, so an ancestor's message survives that
release. The definitions are in `scripts/parts/p4.lean` in this revision (not p2).

`logRecordIvls` records the exact four log intervals: the 40-byte header,
20-byte address, `32 * ntopics` bytes of topics, and `data_n` bytes of data.
`frameLogObjects` reads the live prefix of each frame's list and appends its
exclusive intervals to `frameObjects`. The original seven indices are unchanged.
Thus the existing table, fixed-object, trie, frame, and message disjointness
conditions protect live log records and their private buffers.

There is one source-required sharing case. `emit_transfer_log` in
`guest/src/evm_calls.pnk` stores `vm_system_address` directly in the log address
field. That immutable 20-byte address is covered by the 24-byte global buffer
in `fixedObjects`; it cannot also be exclusively owned by every log.
`logOwnedIvls` removes only that exact interval. `logRecordIvls_covered` proves
that every raw interval is either exclusively owned or this protected address.
No log header can be removed by that rule, since its size is 40, not 20.

## Lifetime inspection

- `op_log` allocates the header, address, topics, and data separately on the heap.
- `emit_transfer_log` allocates the header, topics, and data on the heap and uses
  the shared system address described above.
- `finish_child` assigns `ev := parent` and pops `cur_cont` before calling
  `incorporate_child_on_success`. The merge appends pointers from the retired
  child's list; two live chain frames do not acquire the same log header.
- `frame_epilogue` restores journaled tables when the frame's error is nonzero.
  The added log header separation excludes the R10 table-leaf overlap.
- `frame_exception` changes frame status, gas, output, and continuation status.
  The log extents are separated from those frame and continuation records.
- `process_message_call` returns the successful frame's log list, or null for
  its early empty result. `process_transaction` replaces null with an empty
  heap list, encodes the receipt, and copies the list header and pointer array
  before releasing frame arenas. Log records and payloads remain on the heap.
- `encode_receipt` reads logs and writes fresh allocations. `LogsListOK` and
  `LogEntryOK` are unchanged by R11.

`R11Audit.lean` checks the new log-header separation, unchanged frame-memory
index, ancestor-message condition, interval coverage, and conditional assembly
axioms. Integration proofs remain separate from the specification repair.

## Validation

`assembly`, `assembly_main`, and every R11 regression lemma have only
`propext`, `Classical.choice`, and `Quot.sound` dependencies. Neither assembly
contains `sorryAx`. `LogEntryOK` and `LogsListOK` are byte-for-byte unchanged;
`Assembly.lean` changes only its generated provenance comment.

The source hash, exact build commands, results, compatibility checks, and axiom
outputs are recorded in `R11_validation.json`. The full spec still contains
admitted primitive leaves; this validation is not a completed certificate.
